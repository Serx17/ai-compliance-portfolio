# Архитектура: ИИ-Экран контроля лидогенерации (ФАС)

> Конвейер от рекламного креатива до готового отчёта о нарушениях.
> **Ключевой принцип:** LLM ищет семантику, код проверяет формальные требования.

---

## 1. Общая схема конвейера

```mermaid
flowchart TB
    subgraph INPUT["Вход"]
        A["Рекламный креатив: текст + изображение"]
    end

    subgraph PREPROC["Препроцессор Python"]
        P1["OCR: извлечение текста"]
        P2["Нормализация текста"]
        P3["Извлечение ссылок"]
    end

    subgraph LLM_LAYER["LLM-слой"]
        L1["YandexGPT для демо / Qwen для production"]
        L2["Семантический анализ текста"]
        L3["VLM: поиск логотипов, ERID"]
    end

    subgraph RULES["7 зон контроля Python"]
        Z1["Зона 1: Гарантии доходности"]
        Z2["Зона 2: Указание ПСК"]
        Z3["Зона 3: Использование бренда"]
        Z4["Зона 4: Скрытые комиссии"]
        Z5["Зона 5: Маркировка ERID"]
        Z6["Зона 6: Запрещённые соцсети"]
        Z7["Зона 7: Русский язык"]
    end

    subgraph HITL["HITL"]
        H1["Очередь комплаенс-офицера"]
        H2["Подтверждение или отклонение"]
    end

    subgraph OUTPUT["Выход"]
        O1["Финальный отчёт JSON"]
        O2["PDF с нарушениями"]
    end

    A --> PREPROC
    PREPROC --> LLM_LAYER
    LLM_LAYER --> RULES
    RULES --> HITL
    HITL --> OUTPUT
    H2 -.->|данные для дообучения| L1
```

## 2. Компоненты

| Компонент | Технология | Роль |
|---|---|---|
| **Оркестратор** | n8n | Управление потоком, webhook |
| **LLM (демо)** | **YandexGPT** | Семантический анализ (облако, без GPU) |
| **LLM (production)** | Qwen 2.5-7B через Ollama | Семантический анализ (локально, в контуре) |
| **VLM** | Мультимодальная модель | Поиск логотипов, ERID на изображении |
| **Препроцессор** | Python 3.10 | OCR, нормализация, извлечение ссылок |
| **Правиловый движок** | Python 3.10 | 7 зон контроля |
| **HITL** | n8n Form | Подтверждение/отклонение |

**Инфраструктура:**
- **Для демо:** локальный запуск, YandexGPT по API.
- **Для production:** сервер в контуре клиента (GPU для локальной LLM).

## 3. Пять ключевых trade-offs

### Trade-off 1: LLM для семантики, код для формальных проверок

**Решение:** LLM ищет нарушения в тексте (гарантии, скрытые условия), код проверяет формальные (наличие ERID, ПСК, перевод).

**Почему:** LLM ошибается в формальных проверках. Код детерминирован. Юристу нужны бинарные ответы.

**Цена:** два слоя вместо одного.

**Выигрыш:** надёжность и объяснимость.

---

### Trade-off 2: YandexGPT для демо vs Qwen для production

**Решение:** YandexGPT для демо (облако), Qwen 2.5-7B для production (локально).

**Почему:** демо — без GPU и сервера. Production — данные не покидают контур.

**Цена:** два провайдера в коде.

**Выигрыш:** демо без сервера + production в контуре.

---

### Trade-off 3: Мультимодальность (текст + изображение)

**Решение:** анализ текста (LLM) + анализ изображения (VLM).

**Почему:** логотип банка не виден в тексте. ERID может быть на изображении.

**Цена:** нужна VLM.

**Выигрыш:** полный анализ креатива.

---

### Trade-off 4: HITL — архитектурный принцип

**Решение:** каждый креатив с нарушениями проходит через комплаенс-офицера.

**Почему:** юридические действия инициирует человек. Автоматическая блокировка — риск.

**Цена:** нельзя полностью автоматизировать.

**Выигрыш:** юридическая безопасность.

---

### Trade-off 5: Синтетика для MVP

**Решение:** синтетические 30 креативов с внедрёнными багами.

**Почему:** красная линия (данные клиента не покидают контур) + контроль над багами.

**Цена:** синтетика не покрывает всё разнообразие.

**Выигрыш:** юридическая чистота + демонстрация всех 7 зон.

## 4. Эволюция от Кейсов №1 и №2

| Аспект | Кейс №1 | Кейс №2 | Кейс №3 |
|---|---|---|---|
| **Задача LLM** | Семантический анализ | Генерация текста | Семантический анализ рекламы |
| **Роль правил** | В roadmap | В MVP | **В MVP** |
| **Данные** | 5 WAV | 50 карточек | 30 креативов |
| **LLM** | Qwen 2.5-7B | Qwen / YandexGPT | **YandexGPT / Qwen** |
| **Мультимодальность** | Нет | Нет | **Да** |

**Ключевой сдвиг:** в Кейсе №3 появляется **мультимодальность** (анализ изображений).

## 5. Инфраструктура

**Для демо (без сервера):**
- LLM: YandexGPT (облако, API).
- Препроцессор и правила: Python (локально).
- Оркестратор: n8n (локально, Docker).

**Для production (в контуре клиента):**
- LLM: Qwen 2.5-7B (локально, GPU).
- VLM: мультимодальная модель (локально, GPU).
- Оркестратор: n8n (локально).

**Красная линия:** данные клиента не покидают контур (в production).

## 6. Что НЕ в этой архитектуре (production-слои)

| Слой | Зачем | Почему отложено |
|---|---|---|
| **Fine-tuning LoRA** | Адаптация под клиента | Нужен размеченный датасет |
| **RAG** | Подтягивание регламентов клиента | Нужен доступ к документам |
| **Интеграция с ОРД** | Автоматическая проверка ERID | Требует API-доступа |
| **Multi-tenant** | Один инстанс на несколько клиентов | Требует изоляции данных |

Все слои — в `production-roadmap.md`.
