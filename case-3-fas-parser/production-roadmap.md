# Production Roadmap: Кейс №3 — ИИ-Экран контроля лидогенерации (ФАС)

> Путь от MVP до production: что уже работает, что добавится, в каком порядке.

---

## 1. Что уже есть (MVP)

**Работает:**
- Препроцессор (OCR, нормализация, извлечение ссылок).
- 7 зон контроля (Python-правила + LLM).
- LLM-слой (YandexGPT для демо, Qwen для production).
- HITL-очередь (комплаенс-офицер).
- Генерация отчёта (JSON) и PDF.

**Стек:**
- n8n — оркестратор.
- YandexGPT (демо) / Qwen 2.5-7B (production) — LLM.
- Python 3.10 — препроцессор, правила, PDF.

## 2. Пять production-слоёв

### Слой 1: Fine-tuning LoRA на данных клиента

**Что:** адаптация LLM под конкретную МФО (специфика формулировок, типовые нарушения).

**Зачем:**
- Клиент имеет **свои** правила (что считается нарушением именно у него).
- Партнёрские сети **различаются** по стилю креативов.

**Как:**
- Датасет: **100–500 размеченных креативов** от клиента.
- LoRA-адаптер: обучается за **несколько часов** на GPU.

**Срок:** 2–4 недели после получения датасета.

---

### Слой 2: RAG для регламентов ФАС и клиента

**Что:** подтягивание **актуальных регламентов** ФАС и внутренних правил клиента в промпт.

**Зачем:**
- ФАС **меняет требования** (например, новые ограничения 2026).
- RAG **адаптируется** без переобучения.

**Как:**
- Векторная база: **ChromaDB** или **Qdrant**.
- Эмбеддинги: **E5** или **BGE** (русскоязычные).
- Источники: регламенты ФАС, внутренние инструкции клиента.

**Срок:** 1–2 недели после получения документов.

---

### Слой 3: Интеграция с ОРД (проверка ERID)

**Что:** автоматическая проверка токена **ERID** через API ОРД.

**Зачем:**
- **Валидность токена** — критична для налогового учёта.
- Без проверки — риск штрафа.

**Как:**
- API ОРД (требует аккредитации).
- Проверка: токен **существует** в базе + **привязан** к креативу.

**Срок:** 2–3 месяца (включая согласование).

---

### Слой 4: HITL-цикл (замкнутый)

**Что:** сбор данных от комплаенс-офицера для дообучения LLM.

**Зачем:**
- Комплаенс-офицер **подтверждает/отклоняет** нарушения.
- Данные → **размеченный датасет** для LoRA.

**Как:**
- HITL-форма: отметка «подтверждено» / «отклонено».
- База: накопление пар «креатив → вердикт».
- Переобучение LoRA: **раз в квартал**.

**Срок:** 1 неделя + постоянный цикл.

---

### Слой 5: Multi-tenant

**Что:** один инстанс конвейера на несколько клиентов (МФО, банков).

**Зачем:** экономия инфраструктуры, единое обновление.

**Как:**
- Изоляция данных: **отдельные БД** на каждого клиента.
- LoRA-адаптеры: **разные** для разных клиентов.
- RAG: **разные** векторные базы.

**Срок:** 2–3 недели.

## 3. Дорожная карта по времени

| Этап | Срок | Что делаем |
|---|---|---|
| **MVP** | ✅ готово | Базовый конвейер на синтетике |

## 4. Модели поставки

| Модель | Для кого | Стоимость |
|---|---|---|
| **vGPU-аренда** | Средние МФО | 15 000–18 000 ₽/мес |
| **Bare-metal в контуре** | Крупные МФО, банки | 300 000–500 000 ₽ (CAPEX) |
| **Консалтинг + внедрение** | Все | Ретейнер |
| **SaaS (multi-tenant)** | Малые МФО | Подписка |

**Красная линия:** SaaS — **только для обезличенных данных**. Для реальных ПДн — **только в контуре клиента**.

## 7. Итог

**MVP → Пилот → Production** — три этапа.

- **MVP:** доказательство концепции на синтетике.
- **Пилот:** реальные данные клиента + LoRA + RAG.
- **Production:** HITL-цикл + интеграция с ОРД.

**Ключевой принцип:** каждый слой добавляет ценность, но **не заменяет** HITL. Юридический контроль человека — **незыблем**.
