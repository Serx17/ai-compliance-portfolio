# Ограничения и допущения: Кейс №3

> Этот документ — не «список того, что не получилось».
> Это **карта сознательных границ**: что автоматизируем, что — нет, и почему.

---

## 1. Главный принцип

**Автоматизация не самоцель. Цель — убрать рутину, оставив юридический контроль человеку.**

В рекламной сфере есть задачи, которые **нельзя** автоматизировать. Не «пока не умеем», а **принципиально нельзя** — по закону, этике или из-за природы ответственности.

Этот документ фиксирует такие границы **явно**.

---

## 2. HITL как архитектурный принцип

### Что это значит

**HITL (Human-in-the-Loop)** — каждый креатив с нарушениями проходит через комплаенс-офицера. LLM **не блокирует** рекламу. LLM **находит** — человек **решает**.

### Почему это не «ограничение», а принцип

Автоматическая блокировка рекламы **невозможна** по трём причинам:

#### 1. Юридическая ответственность

Решение о публикации/блокировке — **персональная ответственность** комплаенс-офицера. Никакая LLM не может нести эту ответственность.

#### 2. Регуляторные требования

ФАС предполагает, что решение принимает **человек**. Автоматическая блокировка = **риск** для бизнеса (если ложное срабатывание).

#### 3. Этическая граница

Ложное срабатывание = **потеря бюджета** клиента. Реклама — это **деньги**, и автоматика не должна их «сжигать» без проверки.

### Что HITL даёт

| Выгода | Как работает |
|---|---|
| **Юридическая безопасность** | Все креативы с нарушениями проверяет человек |
| **Данные для дообучения** | Комплаенс-офицер подтверждает/отклоняет → данные идут в LoRA |
| **Объяснимость** | Каждое решение можно проследить |

---

## 3. Что НЕ автоматизируем — и почему

### 3.1. Решение о блокировке креатива

**Не автоматизируется.** Только **человек** решает, блокировать ли рекламу. Автоматика — **только сигнал**.

### 3.2. Оценка креативной концепции

**Не автоматизируется.** «Красиво/некрасиво», «уместно/неуместно» — **субъективная** оценка. LLM может дать **справку**, но не заменит человека.

### 3.3. Работа со сложными случаями

**Не автоматизируется (частично).**
- Новые требования ФАС (которых нет в базе).
- Спорные формулировки (двусмысленные).
- Креативы с иронией/сарказмом (LLM может не понять).

Такие случаи идут **напрямую комплаенс-офицеру**.

## 4. Что НЕ в MVP — и когда будет

| Слой | Что | Почему не в MVP | Когда |
|---|---|---|---|
| **Fine-tuning LoRA** | Адаптация под клиента | Нужен размеченный датасет | Пилот |
| **RAG** | Подтягивание регламентов ФАС | Нужен доступ к документам | Пилот → production |
| **Интеграция с ОРД** | Автоматическая проверка ERID | Требует API-доступа | Production |
| **Multi-tenant** | Один инстанс на несколько клиентов | Требует изоляции данных | Production |
| **Мониторинг дрейфа** | Отслеживание деградации модели | Нужен production-трафик | Production |

Все слои — в `production-roadmap.md`.

## 5. Допущения MVP

### 5.1. Данные

- **Синтетика** (30 креативов) вместо реальных данных.
- **Структура креатива** — фиксированная (текст + изображение).
- **Баги** — типовые, воспроизводимые.

**Допущение:** реальные данные клиента потребуют **адаптации** правил и промптов.

### 5.2. Инфраструктура

- **Демо:** YandexGPT (облако), без GPU.
- **Production:** локальная LLM (Qwen), GPU в контуре клиента.

**Допущение:** для production потребуется сервер в контуре клиента.

### 5.3. Юрисдикция

- **Российская Федерация.**
- **ФАС** + **банковские офферы**.

**Допущение:** для других юрисдикций — переработка правил.

### 5.4. Типы креативов

- **Текст + изображение** (мультимодальность).
- **Видео** — не в MVP.

**Допущение:** видео — отдельный трек.

## 6. Известные ограничения LLM

### 6.1. Галлюцинации

LLM может **выдумать** нарушение, которого нет. **Митигация:** HITL + правило «только с цитатой».

### 6.2. Контекстное окно

YandexGPT Lite — **8K токенов**. Для стандартного креатива хватает. **Ограничение:** для **очень длинных** текстов — фрагментный роутинг.

### 6.3. Дрейф модели

Со временем меняются требования ФАС. **Митигация:** обновление промптов **раз в квартал**.

## 7. Что явно НЕ обещаем

| Не обещаем | Почему |
|---|---|
| **Ноль нарушений** | Часть нарушений — вне зоны конвейера (например, контекст размещения) |
| **Полную замену комплаенс-офицеров** | HITL — принцип, люди остаются |
| **Работу без настройки на клиента** | Промпты + правила — под каждого клиента |
| **Автоматическую блокировку** | Юридически невозможно |
| **100% точность LLM** | LLM ошибается, правила и HITL ловят |

**Эти «не обещаем» — не слабость, а честность.**

## 9. Итог

**Границы — это не слабость. Это — позиция.**

- **Что автоматизируем:** рутину (поиск нарушений, формальные проверки).
- **Что не автоматизируем:** юридические решения (блокировка, оценка концепции).
- **Почему:** закон, этика, ответственность.

**HITL — не «узкое место», а сознательная граница.** Именно это отличает **ответственный LegalTech** от бездумной автоматизации.
