# Case 2: ИИ-конвейер судебных документов

> Автоматизация подготовки судебных приказов для МФО.
> **Ключевой принцип:** LLM генерирует текст, детерминированный код — проверяет формальные требования.

---

## Зачем это

МФО — крупнейший заявитель судебных приказов в России. 🔎

**Проблема:**
- Подготовка одного документа: **1,5–2 часа** ручной работы.
- Возвраты судов из-за формальных ошибок: **8–15%**.
- На 10 000 документов в год нужно **12–15 юристов**.

**Решение:**
- Конвейер: **карточка должника → готовый PDF за 15–20 минут**.
- 7 зон автоматической проверки → возвраты **3–5%**.
- **2–3 юриста** вместо 12–15 (юристы занимаются содержательной работой, а не рутиной).

**Границы:**
- HITL — архитектурный принцип. Подпись и решение о подаче — **только человек**.
- Данные должников **не покидают контур клиента**.

## Ключевое архитектурное решение

**LLM решает языковые задачи. Код — формальные.**

| Задача | Кто решает |
|---|---|
| Генерация текста приказа | LLM |
| Расчёт суммы, периода | Код |
| Проверка реквизитов | Код |
| Проверка приложений | Код |
| Проверка подсудности | Код |
| Проверка исковой давности | Код |
| ПДн третьих лиц | LLM + код (гибрид) |

**Почему так:** LLM ошибается в арифметике и формальных проверках. Код — детерминирован. Юристу нужны бинарные ответы, а не «confidence 0.73».
